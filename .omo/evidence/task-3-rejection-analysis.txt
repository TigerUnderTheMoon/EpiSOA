=== EXECUTIVE SUMMARY ===

The decomposed verifier is rejecting 76.5% of predictions (189/247), causing F1 to drop
from 0.4655 to 0.1468. Our analysis reveals TWO independent failure modes that together
explain 92.6% of all rejections:

FAILURE MODE 1: Rule Precheck (97 rejections, 51.3% of rejected)
  - evidence_span_not_supported: 57 cases (30.2%) - literal text matching false positives
  - stage_mismatch: 47 cases (24.9%) - chain_stages_by_event not populated
  - contradiction_detected: 15 cases (7.9%) - keyword matching false positives
  - stakeholder_not_supported: 4 cases (2.1%) - generic label matching issues
  - Manual spot-check (10 samples): 9 INCORRECT rejections, 1 partially correct
  - Verdict: Rule precheck is rejecting VALID tuples due to overly strict checks

FAILURE MODE 2: LLM Verifier (92 rejections, 48.7% of rejected)
  - ALL 92 have score exactly 0.5 (default fallback)
  - 88/92 (95.7%) have llm_verifier_error
  - The LLM verifier is effectively NON-FUNCTIONAL
  - Default error score 0.5 < 0.75 threshold = automatic rejection
  - Manual spot-check (10 samples): ALL 10 INCORRECT rejections
  - Verdict: LLM NEVER actually evaluates evidence - it's always failing

=== FLAG BREAKDOWN ===
  evidence_span_not_supported: 57 (30.2% of rejected)     <-- #1 FALSE POSITIVE
  stage_mismatch:               47 (24.9%)                 <-- configuration issue
  contradiction_detected:       15 (7.9%)                  <-- keyword false positive
  stakeholder_not_supported:     4 (2.1%)                  <-- matching issue
  no_issue (LLM errors):        92 (48.7%)                 <-- API failures

=== ROOT CAUSES ===

1. evidence_span_not_supported: evidence_spans_supported_by_evidence() does literal
   string matching. Evidence spans contain text extracted from original sources, but
   the stored evidence text is often truncated/formatted differently. The same
   semantic content exists but fails literal match.

2. stage_mismatch: chain_stages_by_event is likely not properly populated for many
   events. The stage field exists but the stage name doesn't match what's in the
   chain stages registry. This is a data configuration issue, not evidence quality.

3. contradiction_detected: Uses simple keyword matching (negative sentiment + positive
   terms in evidence = contradiction). Evidence often contains both complaints AND
   responses (with positive terms), causing false flags.

4. LLM API errors: The verifier's _llm_verify() catches all exceptions and defaults
   to score=0.5. 95.7% of LLM verification attempts fail. Could be API config,
   rate limiting, timeout, or model unavailability.

=== ESTIMATED RECOVERY ===
  Fix BOTH: ~175 of 189 rejected would be recovered (92.6%)
  New rejection rate: ~5.7% (down from 76.5%)
  F1 recovery: ~0.45 (close to pre-verifier 0.4655)
